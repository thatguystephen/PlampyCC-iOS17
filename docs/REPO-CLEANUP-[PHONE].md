## 3. Diagnostics/logging audit and disposition

Audit surface: `src/**` (3300 lines: `Tweak.xm`, `CAMLDiagnostic*`, `CAMLReplacement*`,
`PlampyCCState.h`, `FlashlightOpticalPolicy.hpp`) and `prefs/RootListController.m`,
against the release build (`make package` with no `DIAGNOSTIC` flag).

Findings:

1. **No console logging exists anywhere.** `grep -rn 'NSLog|os_log|printf|fprintf|HBLogDebug' src prefs` finds only `snprintf` serialization calls in `CAMLDiagnostic.xm`. There is no development print/log surface to remove.
2. **The bounded recorder is already compile-gated.** `PLAMPYCC_DIAGNOSTIC_BUILD` (Makefile `DIAGNOSTIC=1`) is the only way recording can be enabled; `kDiagnosticCompileEnabled` is `false` in release and `caml_diag::AdmitObserverBody` short-circuits on it first, so no preference, key, or reset can make a release binary record (`src/CAMLDiagnosticCore.hpp` admission policy; `src/CAMLDiagnostic.xm` `CAMLDiagnosticPrimitiveAdmission`). Every call site (`src/CAMLDiagnosticHooks.mm`, `src/Tweak.xm` glyph traces, `ScheduleGlyphStabilityCheck`) pays exactly one POD-only admission check and early-outs: no message send, retain, allocation, logging, or filesystem work.
3. **One verbose development-only surface ran in release: fixed by compile-gating it.** `RefreshDiagnosticPreferences` + its Darwin preference observer read `kDiagnosticVerbose` (a collector-verbosity flag) from `NSUserDefaults` on every `com.misakaproject.plampyCC.settingsChanged` notification in release builds — pointless work, since verbosity is only consulted past the failed compile gate.

Disposition (release-safe):

- **Changed file: `src/CAMLDiagnostic.xm`** — the verbosity-preference plumbing (`kDiagnosticPrefsDomain`, `kDiagnosticPrefsChanged`, `kDiagnosticVerboseKey`, `RefreshDiagnosticPreferences`, `DiagnosticPreferencesChanged`, and the constructor's refresh + `CFNotificationCenterAddObserver` registration) is now wrapped in `#if defined(PLAMPYCC_DIAGNOSTIC_BUILD)`. Release builds: zero diagnostic preference reads, zero diagnostic notification observers. Collector (`DIAGNOSTIC=1`) builds: behavior unchanged (runtime verbosity selection preserved).
- **Preserved:** the hook/record surface (8 ABI-verified sites, compile-gated), the per-site install-status fault record, the fail-closed session latch, and the `events.jsonl` collector — all reachable only in collector builds. This is the low-cost actionable fault-logging path: a release hook pays one POD check and nothing else.
- **Docs:** `docs/CAML-DIAGNOSTIC-IMPLEMENTATION.md` updated to state the collector-only preference plumbing.
